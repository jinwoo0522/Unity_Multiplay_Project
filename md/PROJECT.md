# Unity 프로젝트 작업 규칙

## Unity 작업 필수 지침

- Unity 관련 작업을 수행할 때는 반드시 `Unity-CLI`(`unity-cli`) 스킬을 읽고 적용한다. 에디터 조작, 씬·오브젝트·에셋 작업, 프로젝트 관리, 빌드·테스트 등 해당 작업에 필요한 스킬 절차를 따른다.
- 스킬을 찾거나 읽을 수 없다면 적용했다고 가정하지 말고, 사용자에게 알린 후 스킬을 사용할 수 있도록 해결한다.

## 변경 및 화면 캡처

- 코드와 에디터 설정을 변경하기 전에 사용자 승인을 받는다.
- 화면 캡처는 조회 목적이어도 반드시 사전 승인을 받는다. 승인 전에는 계층 구조, 오브젝트 속성 등 텍스트 정보로 결과를 확인한다.
- `Assets/Reimport All`은 크래시 유발 우려로 실행하지 않는다. 사용자 승인 여부와 관계없이 금지한다.

## 코드 작성

- 코드 작성 전에 프로젝트 루트의 `CONVENTIONS.md`를 읽고 네이밍과 코드 스타일을 따른다.
- 변경 대상 코드와 관련 구조를 충분히 읽고 파악한다. 일부 코드만 보고 나머지 동작을 추측하지 않는다.
- 게임 로직은 서버 권위 구조를 따른다. 클라이언트는 입력만 전송하고, 검증과 판정은 서버에서 수행한다.
- 클라이언트 입력값을 신뢰하지 않으며, 중요 데이터는 서버에서만 관리한다.

## 에셋 참조 및 변경

- 에셋을 참조하기 직전에 현재 프로젝트의 실제 파일 경로와 GUID를 확인한다. Animator Controller 등 참조 정보를 작성할 때도 동일하게 적용한다.
- 이전 대화에서 확인한 경로나 GUID를 그대로 재사용하지 않는다. 에셋이 교체·삭제·이동되었을 가능성을 확인한다.
- 에셋을 교체·삭제·이동하기 전에 참조하는 곳을 확인하고 변경 영향을 파악한다.

## 프로젝트 탐색

- 코드와 에셋 탐색은 `Assets/`에서 시작하고, 아래 경로를 우선 확인한다.
- 프로젝트 전체를 무차별적으로 탐색하지 않는다. `Library/PackageCache`와 작업에 무관한 VFX 파일 등은 기본 탐색 범위에서 제외한다.
- `TASK.md`, `PLAN.md` 등 Markdown 문서는 워크트리 루트를 기준으로 찾는다.

| 대상 | 우선 탐색 경로 |
|---|---|
| 스크립트 | `Assets/Script` |
| 프리팹 | `Assets/Prefabs` |
| 데이터(ScriptableObject) | `Assets/Resources/Data` |
| 애니메이션 | `Assets/Animation` |
| Animator Controller | `Assets/Animator` |
| 씬 | `Assets/Scenes` |
